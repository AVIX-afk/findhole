# Playbook: games and game mods

- **Sources:** developer patch notes and Steam announcements, Steam reviews (recent and all-time) and discussion threads, official forums/known-issues pages, ModDB, Nexus Mods, Steam Workshop, engine/SDK docs, gameplay video, patch-tracking fan sites. Local game files only if the user authorizes it.
- **If Reddit/Discord are blocked:** use Steam discussions, patch-note aggregators, press coverage of developer statements, and fan wikis. Say the community sample is narrower.
- **Review scores drift:** secondary sources quote different percentages from different dates. Report the range with dates rather than picking one.
- **Change surface:** distinguish UI/data/config changes, scripted mods, runtime hooks, asset edits, save edits, core simulation rewrites and server-authoritative logic. Check whether the behavior is client-side or server-side.
- **Owner-only holes:** server-authoritative logic, matchmaking, progression and anything behind kernel-level anti-cheat can only be fixed by the developer. For these, the outsider action is usually adopt a workaround or watch. Never recommend disabling or bypassing anti-cheat.
- **Developer intent:** check pre-launch statements, FAQs and Early Access notes for deliberate tradeoffs before calling something a defect.
- **Version:** search up to the current build. Check mod-loader game version, update stability, multiplayer/EULA rules, dependencies and licensing; a mod that worked on an older build may not work now. Workshop support does not imply arbitrary code patching.
- **Saturation check for companion tools:** maps, loadout builders, calculators, databases and LFG sites appear quickly for popular games. Check for these before proposing one.
- **Simulation balance:** use repeated or seed-controlled comparisons where possible; keep legitimate randomness.
- **Rollback:** clean original install, backed-up saves/configs, isolated modifications, a simple disable toggle.
